# Luma

一个自由的、无限制的 agent。前端好用（Web、iOS）。循环复用 pi，也允许换成别的
agent loop。图片和视频生成是一等能力。记忆、文件、联网搜索是 agent 该有的。
后端随便接——远程 API 或本机 ComfyUI。

上面这句话是产品。其余文档只解释代码怎么把它做出来。

---

## 从这句话推出的形状

**自由、无限制。** 不在 Luma 里做内容过滤、拒答词表、安全 LoRA、审核开关。
过滤如果存在，在上游网关或下游专门组件里，这里不重复。默认提示词按「直接完成
委托」写，人可以在设置里改。

**前端是皮肤。** 服务端是唯一真相。Web 和 iOS 都是 `/v1` 的客户端，没有私有
端点，不能各写一套业务。新能力先出现在 HTTP 上，两个前端再跟上。

**循环不自研。** 对话回合复用 pi 的 `Agent` / `agentLoop`（session 树、压缩、
流式、工具调度）。Luma 做它外面的那一层：HTTP 生命周期、投影、审批、工具装配、
生成队列。以后要换别的 loop，换的是这一层的后端，不是再写一套 turn 状态机。

**生成是一等能力。** 文生图、图生图、文生视频、图生视频，走同一套 adapter +
job 队列。创作台的表单和模型的工具来自同一份 schema。ComfyUI 不是 MCP 特例，
是一个刚好听 `127.0.0.1:8188` 的 adapter。

**标准 agent 能力默认有。** 记忆、文件库（含检索）、联网搜索。代码执行、
skills、MCP 也在，按需开关。它们让 agent 做得成事，但生成和对话不是它们的插件。

**后端可插。** 一个 provider 行 + 一个 model 行就能接 OpenAI 兼容接口、
Anthropic、本地 llama、托管生图/生视频、ComfyUI workflow。MCP 用来接「还没有
adapter 的东西」，不是用来绕过已经有的生成层。

**状态在本机。** SQLite 和文件目录就是全部状态。没有账号体系，没有云端副本。
访问码证明你是这台机器的人；多设备是同一服务的多个客户端。

---

## 明确不是

- 多人协作、权限、分享给陌生人。
- 公共托管平台。
- 训练或评测模型。
- 遥测。日志留在本机。

## 现在还没对齐的地方

**换 loop 的成本比这份文档听起来大。** 循环通过 `LoopFactory` / `LoopStart` /
`LoopEvent` 接到 Runtime，pi 是默认 factory（`createPiLoop`），`Agent` 的构造和
`AgentEvent` 的订阅确实只在那一个文件里。但边界上的类型是 pi 的类型
（`AgentMessage`、`AgentTool`、`Model`、`StreamFn`），session 树、工具、模型
注册表、压缩也都是 pi 的。所以现在这道缝是「换引擎从哪里下手」，不是「换引擎
只要写一个 factory」。要真做到后者，得先把边界换成 Luma 自己的消息与工具类型，
那是一次有意的重写，不是顺手能补的。

**ComfyUI 这条路只在装了它的机器上验证过。** 它是 adapter，没有特例；但
`scripts/comfy.ps1` 只覆盖 Windows 的 Desktop 安装，POSIX 上要人自己开。预设
绑着本地模型而 8188 没人听时，生成会失败并说清楚该启动什么，不再是一句
`fetch failed`。
