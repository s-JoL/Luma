# 产品形态

`00-product.md` 写的是机器上已经立住的形状：自由、无限制、前端是皮肤、生成是
一等、状态在本机。这一份写的是**人怎么用它**——从真实用法出发，对照 2026 年真
实存在的产品，把五栏能力台收成一个每天都会打开的个人工作室。

原则仍以 `00` 为准。这里改的是信息架构、界面和几处会话元数据，不是再写一套后端。

可点的原型：[`prototypes/index.html`](prototypes/index.html)（静态页，不接后端，
双击就能开）。

---

## 一、用户在干什么

不是「又一个 ChatGPT 克隆」。第一感觉是：**不受限制的对话，而且图和视频从第一天
就在场。** 日常不按功能栏走，是按一次委托打开一个会话：

| # | 打开一个会话是为了 | 今天怎么凑出来的 |
|---|---|---|
| 1 | 让 agent 做事：搜、读文件、改东西、记下来 | 空白对话 + 设置里碰巧开着的工具 |
| 2 | 边聊边出图、改图、出视频 | 对话里碰运气让模型调工具，或离开对话去创作台填表 |
| 3 | 一次临时的 roleplay | 同一条对话列表，没有角色、没有「用完就扔」 |
| 4 | 一段连续的图文故事 | 长对话 + 手动去创作台补图，连续性全靠人记 |
| 5 | 网上找资料、上传喜欢的作品当参考、有记忆 | 搜索是工具，参考是附件，记忆是另一栏 key/value |

主业现在是图。**视频是明确要长进来的那一等能力**，不是以后再挂的插件。

这五件事共享同一台机器、同一份作品、同一套记忆。它们不是五个产品——但也不该是
同一个空白对话框。

---

## 二、现在的界面在用能力说话

Web 和 iOS 都是五栏：对话 / 创作台 / 文件 / 记忆 / 设置。对话列表是扁平标题
（`app.tsx` 的 `groupByDay` + `conversation.title`）。创作台是一张 schema 表单加
砌体图库。记忆是全局 key/value。文件是图书馆。

这对实现是诚实的——后端本来就是这些能力。对人是错的：

- **打开产品看到的是能力，不是委托。** 「新对话」不区分做事、出图、入戏、写故事。
- **出图被拆成两条路。** 对话里靠模型自己调工具；要旋钮就去另一栏填表。人的真实
  路径是「看着一张图改、让它动、把它写进故事」，不是先选栏目。
- **记忆和文件占了两个常驻栏。** 它们是会话的给养，不是每天要去报到的地方。
- **手机抄了桌面的五栏。** 「打开就是上一段对话、拇指够得到」这种手感，五栏做不
  出来。
- **视频只在创作台有一个标签页。** 从已有的图「让它动」应该是作品上的一个动作。
- **失败在最后一刻才说话。** 绑了本机 ComfyUI 而 8188 没人听时，报错是对的
  （`03-generation.md` 有意为之），但人是在提交之后才知道的。

后端其实够用：一种 session 树、一条 job 队列、一种 `GeneratedAsset`、全局记忆、
文件库、搜索、审批、`steer`。缺的是**会话的姿势**和**作品上的动作**。

## 三、调研：市面上已经存在什么

按人真的会打开的来看，不按 star 数。以下是核对过的事实，不是印象。

### 开源前端

| | 近在哪 | 死在哪 |
|---|---|---|
| **SillyTavern** | 角色卡（V3 规范，JSON 塞在 PNG 的 `tEXt` 里）、World Info / lorebook 可绑到角色/persona/单条聊天、A1111 与 ComfyUI 出图扩展、社区卡海量 | 图和视频是扩展，不是骨架；**没有官方移动端**，Android 靠 Termux、iOS 只能浏览器连主机；agent 是附属；界面是给愿意配五十个采样器的人 |
| **Open WebUI** | 干净的 ChatGPT 皮、Ollama 原生、RAG 最强（collection + 混合检索）、原生接 A1111/ComfyUI/DALL·E、SearXNG | 多用户与 RBAC 的团队气质；图仍是「聊天里的一个插件」；没有角色/故事原语；手机是 PWA |
| **LibreChat** | 供应商最多、原生 MCP、agent、对话分支、插件即开即用 | 无限制支持差；图弱；LDAP/OIDC/SAML 这类企业件把个人工作室压歪；要 MongoDB |
| **LobeChat** | 三家里 UI 最好看、插件市场、移动端 PWA 体验最好 | 生成靠插件桥接（DALL·E / Midjourney），不是一等；agent 浮 |
| **Cherry Studio / Chatbox / Jan / AnythingLLM** | 一个桌面窗口接很多模型，装起来快 | 生成不是一等；agent 浮；手机弱或另起一套 |

三家主流自托管前端在 2026 年的共同点：**RAG 和多供应商已经卷完了，生成仍然是
挂件，角色和故事根本不在词汇表里。**

### 原生 App

| | 近在哪 | 死在哪 |
|---|---|---|
| **Locally AI** | 2026 年初被 LM Studio（Element Labs）收购，成了官方移动端；**LM Link 让手机连回家里那台跑 LM Studio 的机器**——「手机是家里那台机器的遥控器」这条路已经有人在走了 | 只有对话和看图，没有生成、没有 agent、没有作品库；两端都要 LM Studio 且要账号；iPhone/iPad only |
| **ChatGPT / Claude / Grok / Gemini App** | 会话、记忆、agent、跨设备，业界最熟的手感 | 限制就是产品本身 |
| **Enchanted / Pal / ChatterUI 一类** | 原生、轻、连自建后端 | 只是一个聊天壳 |

Locally 这条更新值得认真对待：**「打开就是会话、拇指够得到、模型在家里」不再是
空位。** Luma 和它的差别不在「有没有 App」，而在这个 App 后面站着的是一台能出
图、出视频、会做事、记得住的机器，而不是一个推理进程。

### 创作与故事

| | 学什么 |
|---|---|
| **Midjourney / Runway / Kling** | 作品上的动作，而不是首页上的表单。图生视频是主路：Kling 3.0 Motion Control 这类接口就是「一张角色图 + 一段参考」→ `task_id` → 轮询或 webhook，5–10 秒的片子跑 2–15 分钟。**异步、要等、要通知**是这类能力的天性 |
| **NovelAI** | 故事 + 图 + lorebook，限制少；但闭源、画风窄、没 agent、没视频、没手机 |
| **Sudowrite Story Bible / Novelcrafter Codex** | 连续性是一个可编辑的对象，不是靠模型记 |
| **Story Spark / StoryPic / ToonyStory 这批 2026 的图文书工具** | 它们全都在解同一个问题：**角色漂移**。共同答案是「角色定义一次，之后每一次出图都把同一份身份锚（参考图 + 规范化外貌描述）重新注入 prompt」。学术侧（S2ED、CharCom）也是同一个结论：把叙事推理和图像合成解耦，用显式状态在帧之间传递 |

### 角色向

Character.AI / JanitorAI / Chub：开箱即角色、卡有生态。审核墙是它们的产品；图和
视频不是从第一天就在。

### 裂缝

要么会聊不会画，要么会画不会聊，要么会演不会做事，要么桌面好而手机是附属，要么
自由但只适合坐在电脑前配一晚上。

Luma 已经站在裂缝正中间：本机、无限制、对话和生成同一套 `/v1`、Web 和 iOS 同一份
API。要做成「适合人」而不是「能力演示」，差的是**会话怎么开、作品怎么用、手机
怎么拿**。

### 该偷的手艺

- **Locally / ChatGPT App**：打开就是会话。底栏不超过三格。作曲栏是产品本体。
- **SillyTavern**：角色是对象——名字、外观、性格、开场白、你是谁。**并且能导入
  社区的 V2/V3 PNG 卡**：这是别人十年攒下的内容，一个解析器就能接上。不要卡市场、
  不要表情差分、不要群聊、不要两百个扩展开关。
- **Sudowrite / Novelcrafter / 2026 那批图文书工具**：连续性是显式对象；身份锚每
  次重新注入。这是「连续图文故事」唯一被证明有效的做法。
- **Claude Projects**：给养是显式的知识库，不是玄学。Anthropic 自己写着：同一个
  project 里的会话之间**不会**自动共享上下文，除非你把它放进知识库。这句话该原样
  抄进 Luma 的记忆设计——三层给养必须看得见、改得动。
- **Runway / Kling**：一张图上就有「让它动」。表单是检查器，不是目的地。
- **Claude**：对话是给人读的。栏宽、暖底、工具块可展开，不要做成 IDE 的时间线。
- **Grok / 所有视频工具**：进行中的事必须一等。人不会盯着页面等两分钟。

### 明确不学

- 酒馆的扩展市场、正则脚本、群聊、表情差分。
- Open WebUI / LibreChat 的多人、权限、SSO、模型广场。
- ChatGPT 的 GPT Store 和功能条膨胀。
- 端侧推理（那是 Locally 的产品。Luma 的手机端是遥控器，不是推理器）。
- 公共图库、把对话导出成给陌生人看的东西。

## 四、结论：应该做成什么

比 `00` 那句更朝向人的一句：

> **个人的、无限制的创作会话。打开一次委托，就能做事、出图出视频、入戏、写带图的
> 故事。参考和记忆跟着你。手机和电脑是同一台机器的两块屏幕。**

### 概念模型

三个对象，别的都是它们的视图。

```
会话 Session ── 有一个姿势，有自己的给养，产出作品
   │
   ├── 姿势 Posture   对话 · 做事 · 创作 · 角色 · 故事
   │                  只改：空状态、一层提示词、默许工具、侧栏、作曲栏捷径
   │
   ├── 给养 Provision 全局记忆（跨会话） · 会话记忆（角色卡 / 连续性） · 参考板（视觉锚）
   │
   └── 作品 Work      图和视频同一格。动作在作品上：改这张 / 让它动 / 放到参考 / 血缘
```

**姿势不换引擎。** 同一个 pi 循环、同一条 job 队列、同一套 `/v1`。它改变的只有
五件事：

```
姿势   空状态在说            侧边放什么              作曲栏多什么        默许工具
对话   直接说                无（转写更宽）          附件                全局设置
做事   要办成哪一件          在用的文件、待批        附件、搜索          搜索/文件/编码
创作   想看见什么            参考板、进行中的 job    出图、让它动        生成三件
角色   你是谁、对方是谁      角色卡、你的 persona    附件（很少）        少：不打断入戏
故事   这一段从哪起          连续性：人物/地点/已发生 续写、画这一幕、让它动  生成 + 文件
```

「对话」是默认，一键就进。其余四个是同一条会话被放进一种姿势。姿势可以中途改，
角色卡和连续性不会因为改姿势丢掉。

用户永远看不到「姿势」这个词。他看到的是四张卡片：做事 / 创作 / 角色 / 故事。

五件用法对上：

1. 做事 → 姿势「做事」。搜索、文件、编码、审批在场。
2. 对话出图出视频 → 姿势「创作」，或者默认对话里直接说。表单不是目的地。
3. 临时 roleplay → 姿势「角色」，可标临时；结束能扔，不脏列表。
4. 连续图文故事 → 姿势「故事」。连续性卡片 + 身份锚 + 场景图进转写。
5. 资料 / 参考 / 记忆 → 不是姿势，是给养。任何会话都能用。

### 为什么不是别的方案

| 方案 | 为什么否掉 |
|---|---|
| **A. 保持五栏，只把视频做厚** | 最省事，也最不解决问题。用法 3 和 4 仍然无处安放，出图仍然两条路，手机仍然是缩略的桌面 |
| **B. 抄 Projects：做「项目」容器** | 项目是给长期工作的，Luma 一半的会话是一次性的（临时 roleplay、随手一张图）。强迫先建项目再说话，等于给每次委托加一道门。给养跟着会话走就够了；真需要跨会话复用的（角色卡、参考板）单独存 |
| **C. 抄酒馆：以角色卡为中心** | 那会把一个能做事的 agent 变成一个聊天玩具。用法 1 和 5 会被挤出去 |
| **D. 姿势（选定）** | 加的是会话上的一点元数据和四张卡片，换来五种用法各自有正确的空状态、侧栏和捷径。运行时一行不用改 |

## 五、信息架构

### 常驻位置

| 桌面 | 手机底栏 | 是什么 |
|---|---|---|
| 会话（左列表 + 主区） | **会话** | 80% 的时间在这里 |
| 作品 | **作品** | 图和视频、上传的参考、血缘、动作 |
| 我的（头像入口，不占栏） | **我的** | 记忆、文档、连接状态、设置 |

从五栏收到三处。**创作台不再是一个栏目**，它变成三种入口下的同一个检查器：

- 会话作曲栏的「出图 / 改图 / 出视频」
- 作品上的「改这张 / 让它动」
- 创作/故事侧栏的「精确参数」（打开今天的完整 schema 表单）

`POST /jobs`、`GET /studio/tools` 的 schema 全部留着，`/studio` 路由留作检查器的
深链——只是人不再需要先走进一个叫创作台的房间。

文件库拆开：**媒体进作品，PDF 和笔记进「我的 / 文档」**，会话里随时附。记忆不再
占常驻栏，去「我的」和会话里的「记住这句」。

### 页面清单

```
会话
  首页（没开会话时）          继续上一段 · 新会话 · 四张姿势卡 · 进行中 · 待批
  会话列表（左栏，桌面常驻）  姿势标 · 封面 · 进行中小点 · 临时标 · 跨会话搜索
  会话                        转写 + 作曲栏 +（按姿势的）侧栏
    对话 / 做事 / 创作 / 角色 / 故事
  检查器（抽屉）              完整生成参数表单
作品
  网格                        全部 / 图 / 视频 / 参考 / 角色 · 顶部钉住进行中的 job
  作品详情                    大图 · 改这张 / 让它动 / 放到参考 / 存到相册 · 血缘
  参考板                      集合：画风 / 人物 / 场景 / 光
我的
  记忆                        全局 key/value + token 预算
  文档                        上传、笔记、检索、索引状态
  连接                        连的是哪台 · 队列 · 后端健康
  设置                        见 §六
  首次配置                    只在没有可用对话模型时出现
```

## 六、逐屏

### 首页（打开产品第一眼）

不是一个空白输入框，也不是功能清单。

- **继续上一段**（最大的一块，带封面和最后一句）
- **新会话**（一键，进默认对话）
- **四张姿势卡**：做事 / 创作 / 角色 / 故事。每张一句说明 + 一个「开始」
- **进行中**：「两段视频在排队 · 约 3 分钟」→ 点进作品或回原会话
- **待批**：有审批时才出现，点进那一段
- 顶部一个搜索框，跨会话搜转写（`GET /conversations/search` 已有）

角色卡片上可以「用一张已存的卡」或「这次只用，不保存」。除此之外，新会话不要先
问二十个问题。

### 会话列表

不是扁平标题。每行看得见：姿势标记、封面（最近一张图或角色脸）、进行中的小点、
临时标。分组仍按时间。

### 会话骨架（五种姿势共用）

```
┌ 顶栏  姿势标 · 标题 · 模型切换 · 工具在不在场 · 侧栏开关
├ 转写  流式 · 工具块（可展开）· 图与视频 · 审批卡 · 编辑/重试/继续
└ 作曲栏 输入 · 附件 · 停止 ·（按姿势的）捷径
```

三处细节：

- **进行中的作曲栏不该是灰的。** `POST /conversations/:id/steer` 已经在 `/v1` 上，
  两个前端都还没接。run 在跑时，输入框应该说「插一句，这轮完了算进去」。
- **点开任意一张图**，都得到同一组动作：改这张 / 让它动 / 存到作品 / 放到参考 /
  看血缘。转写里的图和作品页里的图不该有两套菜单。
- **生成后端不可用时，提前说。** 绑定的后端没配密钥、或本机 ComfyUI 没在听 8188，
  作曲栏的「出图」旁边挂一个可点的提示，而不是等提交完再报错。

### 五种姿势

**对话。** 今天的转写，去掉「要出图得去创作台」这个暗示。模型出的图就是作品。
空状态一句「直接说」。

**做事。** 侧栏是「这一段在用的」：附过的文件、检索命中、待批。审批继续是转写里
的卡片（不是模态），但首页要有待批入口——人会离开这段对话去干别的。

**创作。** 侧栏是参考板（本次钉住的图）+ 进行中的 job。纯聊天出图可以，拉开检查
器调比例/时长/seed 也可以。**参考板里的图自动作为 `additional_source_image_ids`
带进生成调用**，不用每轮重新附。

**角色。** 侧栏是一张卡：名、外观、性格、开场白、你的 persona、可选世界注记。
临时会话在列表里标「临时」，归档或删除是一等动作。卡可以保存，下次开会话能选，
**也可以导入社区的 V2/V3 PNG 角色卡**。不做群聊、不做人设市场、不做表情图。
角色的脸是一张生成或上传的图，它同时就是这段会话的身份锚。

**故事。** 侧栏是连续性，也就是这段会话的记忆：

```
人物   名字 + 一句规范化外貌 + 锁定的参考图        ← 身份锚
地点   名字 + 一句环境描述 + 可选参考图
已发生 时间顺序的要点，人可改，模型可追加（要人确认）
画风   一张或几张参考图 + 一句风格词
```

作曲栏三个捷径：**续写 / 画这一幕 / 让这张动**。「画这一幕」的提示词由模型从刚
写的那段来，参考图从人物锁和画风锁里来——这就是调研里那批图文书工具的做法，也是
「连续的图文」和「人来回拷提示词」的区别。

### 作品

一格网，图和视频同一种磁贴（今天已经是了）。加上：

- 筛选：全部 / 图 / 视频 / 我上传的参考 / 某段会话里出的
- 点开：改这张 / 让它动 / 放到某段会话的参考 / 存到系统相册 / 血缘
- **上传就是「加入参考」**，不是先去文件栏再想起来
- 进行中的 job 钉在顶上，锁屏回来还在（队列本来就这么工作）

视频不是二等：同一格、能直接播、能从一张图发起。但**视频当不了源**
（`03-generation.md`：父本只有 `img_`），所以视频磁贴上不要出现「用这段再生成」，
只有下载、存相册和血缘。

### 我的

记忆 · 文档 · 连接 · 设置。手机上这一栏还要回答「我连的是家里哪台、队列里还有没
有活、哪个后端是红的」。

### 设置

今天六页（提供方、对话模型、工具与后端、能力、提示词、安全）对部署是对的，对每天
打开的人偏工程师。**保留全部能力，只改分组和第一次。**

| 组 | 页 | 人来这里是为了 |
|---|---|---|
| 连接 | 提供方 | 换网关、改密钥。密钥只提交不回读 |
| 连接 | 对话模型 | 启用、固定到切换器、设默认、从提供方拉清单批量加 |
| 连接 | **后端健康**（新） | 一屏看清：每个提供方通不通、ComfyUI 在不在听 8188、搜索和 embedding 配没配。今天这些只在失败时才说话 |
| 生成 | 图与视频后端 | 默认生图 / 改图 / 视频三个槽。Comfy 工作流绑定仍只在网页改（iOS 继续不碰 `params`，那是合并语义，渲染一半会抹掉另一半） |
| 能力 | 搜索 / 检索 / 编码 / MCP | 按需开关。关掉的工具不出现在 agent 面前 |
| 人格 | 提示词与姿势 | 全局提示词、工具提示词、四个姿势各自那一薄层、已存角色卡 |
| 系统 | 外观 | 主题、字号。够用就别做皮肤市场 |
| 系统 | 安全 | 访问码、TOTP、设备。写操作继续 step-up |
| 系统 | 数据 | 这份目录多大、作品占多少、**没有云端备份**——说清楚 |

**第一次配置**（只在还没有可用对话模型时出现）：

1. 已经用访问码进了门
2. 加一个提供方：地址 + 密钥，或者跳过（只用本机）
3. 从清单里勾对话模型、生图、视频；勾完就是默认
4. 结束。这些页之后都还在，只是不再挡在第一次说话前面

## 七、记忆与参考：三层，看得见

今天 `memories` 是一层：全局、每轮按预算塞进系统提示。创作者实际有三层。

| 层 | 活多久 | 例子 | 存在哪 |
|---|---|---|---|
| 全局记忆 | 直到人删 | 「我喜欢胶片、浅景深」「回复里不要加提醒」 | 现有 `memories`，入口移到「我的」 |
| 会话记忆 | 这段委托 | 这个角色的眼睛颜色、这一章谁已经死了 | 角色卡 / 连续性，会话行上的 JSON，不进全局表 |
| 参考板 | 直到人删 | 喜欢的作品、这个人物的脸、这个故事的画风 | 作品里的集合，会话可以钉一块 |

「上传我喜欢的作品当参考」是参考板，不是文件栏里一张匿名图。人给它名字和用途
（画风 / 人物 / 场景 / 光）。

**身份锚怎么进 prompt。** 这是用法 4 能不能成立的关键，也是调研里所有图文工具的
共识：不能指望模型记得住。会话钉住一块参考之后，生成工具的装配层做两件事：

1. 参考图的 id 进 `additional_source_image_ids`（改图/图生视频的源）
2. 参考条目上那句规范化描述追加到 prompt 尾部（「Aya：银灰短发，左眉疤，墨绿风衣」）

两件都发生在服务端的工具装配里，客户端不拼提示词（`06-clients.md` 的共同规则）。

全局记忆的写入规则不变：人明确说「记住 / 忘掉」，或自己在「我的」里改。**不做静默
画像。**

## 八、视频怎么算一等

管道是齐的：四种操作、job 队列、`GeneratedAsset`、转写/图库/文件库都能播。产品上
差的是「从已有的图出发」这条主路——人手里已经有图了，视频是让那张图动，不是重新
写一段文生视频提示词。

- 每张图上都有**让它动**。带这张作为 `image_to_video` 的源，检查器只问时长和镜头。
- 故事里，「画这一幕」→「让这张动」是两个相邻动作。
- 队列按分钟说话，不按百分比空转。托管视频跑几分钟是常态（Kling 这类接口官方就说
  2–15 分钟），界面必须假设人已经走开了。
- 不做时间线剪辑、多镜拼接、字幕轨。那是剪辑软件。Luma 出的是一段段能播的镜头，
  血缘指向源图。

## 九、等待、失败、通知

这是「能用的产品」和「demo」之间最实在的一段。

**队列是一等。** 进行中的 job 在三个地方看得见：首页一条、作品页顶部钉住、原会话
侧栏。重启后仍在（排队的重新入队，带 `provider_job_id` 的托管视频接着等，不付第二
次钱）。

**通知已经有一半。** Web 的 `notify.ts` 在标签页隐藏时发通知；iOS 的 `Notifier` 在
App 不在前台时发本地通知，并且用 provisional 权限，不弹第一道打扰。

**剩下的一半是诚实的短板**：iOS 离屏几秒就被挂起，一个十分钟后才完成的 job，App
根本没机会发那条本地通知。自托管没有 APNs，不该为此引入推送服务。可行的是两条：
用 `BGAppRefreshTask` 机会性地查一次 `GET /jobs?status=running`；以及回到前台时，
队列和结果必须**立刻**在眼前，不用人去找。这条要写在产品文档里，而不是让人自己
发现。

**失败要指向下一步。** 错误信封的 `message` 是给人也是给模型看的
（`05-api.md`）。界面上再进一步：「ComfyUI 没在 8188 上」后面跟一个「去设置换后端」
和一个「重试」。

## 十、手机就是产品，不是网页的缩略

目标手感对标 Locally：打开、上一件事还在、拇指发一句、图出来能接着改。做不到端侧
离线——Luma 的模型在家里或网关上，手机是遥控器。要做到的是：

- **底栏三格**：会话 / 作品 / 我的。不要五栏平权。
- 会话地址继续写在路由里，后台被杀还能回来（已经这样）。
- SSE 被掐就轮询，回来用 `after=` 续（已经这样）。
- 一张图的动作（改 / 动 / 参考）必须是 sheet，不要把桌面的左右分栏塞进来。
- 角色卡和连续性是一张可拉起的卡片，不是右侧栏缩水。
- 生成参数继续用今天 iOS 那排**可点胶囊**——那个设计比桌面表单更适合拇指，值得
  保留并且反向影响桌面的检查器。
- 审批继续做转写内卡片；首页的待批入口是为了人已经离开那段对话。
- 设置里提供方和对话模型继续能在 App 里改；生成模型的 `params` 仍只在网页改。

iPad 保持分栏：左列表、中转写、右姿势侧栏。

## 十一、明确不做

会把工作室做成另一个产品，或者做成酒馆的：

- 多人、分享给陌生人、角色市场、GPT 店
- 内容过滤、拒答开关、安全 LoRA（过滤不在 Luma 里叠，见 `00`）
- 群聊、表情差分、正则脚本、两百个采样预设
- 小说工房：时间线、多视角工程、导出 EPUB
- 云端账号、遥测、把 `data/` 同步到别人的服务器
- 端侧模型下载（手机不是推理器）
- 把 MCP 再做成第二条出图路径

## 十二、和现有代码怎么接

不改运行时也能做出这个形态。新增的是会话上的一点元数据，以及前端怎么看它。

| 已有 | 形态上变成 | 要动什么 |
|---|---|---|
| `conversations` 一行 | 加 `posture`、`ephemeral`、`character_id`、连续性 JSON；列表投影多一个封面 | schema + 投影 + `05-api.md` |
| `messages` + 转写 UI | 主表面。图上出现动作；run 进行中出现转向 | 两个前端 |
| `jobs` + `/studio/tools` schema | 检查器，不是栏目。作品顶部钉住活的 job | 只改前端 |
| `image_assets` / `video_assets` / gallery | 作品页。上传 = 参考 | 加一个「集合」概念 |
| `memories` | 全局层，入口从栏移到「我的」 | 只改前端 |
| `files` | 媒体进作品，文档进「我的」，会话附件不变 | 只改前端 |
| 提示词两槽 | 再加四个姿势的薄层 | `prompts/defaults.ts` + 设置页 |
| 工具装配 | 钉住的参考进 `additional_source_image_ids` + 身份锚追加到 prompt | 服务端 |
| 审批 + `steer` | 首页待批入口；转向接进作曲栏 | 前端（`steer` 后端已就绪） |
| iOS 五栏 | 三栏，侧栏改 sheet | iOS |

`/v1` 仍然是唯一真相。新字段先上 HTTP，两个前端再跟。

### 分期

**P0——形态立住。** 会话姿势（元数据 + 四张卡 + 空状态 + 侧栏 + 作曲栏捷径）；三栏
信息架构；作品页上的四个动作（含「让它动」）；检查器抽屉替掉创作台栏目；首页
（继续上一段 / 进行中 / 待批）；作曲栏接 `steer`。

**P1——让它连续。** 参考板与身份锚注入；角色卡（含 V2/V3 PNG 导入）与临时会话；
故事连续性侧栏与三个捷径；设置重新分组 + 首次配置向导 + 后端健康页；iOS 收成三栏
加 sheet。

**P2——长住。** 队列的 `BGAppRefreshTask` 补丁；作品按提示词/模型搜索；用量与花费
（`models.pricing` 已经在表里）；键盘快捷键。

## 十三、验收：怎么算做对了

不用埋点。这台机器只有一个用户，问这十个问题就够：

1. 打开产品，是不是先回到上一段，而不是先看见一个空输入框？
2. 出一张图，需要离开当前会话吗？
3. 一张图上，能不能一步「让它动」？
4. 临时的 roleplay 结束之后，会话列表脏了吗？
5. 故事的下一张图，人物长得还像上一张吗？人有没有手动拷过提示词？
6. 上传一张喜欢的作品，之后的生成有没有真的带上它？
7. 视频跑着的时候锁屏，回来第一眼能不能看到它？
8. ComfyUI 没启动，是在提交前知道的，还是提交后？
9. 第一次进来的人，说出第一句话之前，需要读文档吗？
10. 手机上改一张图，是一张 sheet 还是一套桌面表单？

## 十四、还没定的

- **姿势能不能中途切换**，切了以后角色卡怎么办。倾向：能切，给养保留，只换侧栏和
  提示词层。
- **连续性该不该自动追加。** 模型标记「这一幕发生了什么」再由人确认，还是全靠人写？
  倾向：模型草拟，人一键确认，绝不静默写入。
- **参考板要不要跨会话共享一个「默认画风」。** 倾向：要，但必须显式钉住，不做隐式
  全局风格。
- **角色卡导入的兼容边界。** V3 规范里 lorebook、问候语数组这些字段，导入到什么
  程度算够用。
- **iOS 后台通知**：`BGAppRefreshTask` 的机会性刷新在真机上到底有多可靠，需要实测
  才能决定要不要写进文档承诺。
